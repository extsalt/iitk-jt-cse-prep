# IIT Kanpur Junior Technician (CSE) exam prep

This folder holds mock tests and practical notes for Ganesh's IIT Kanpur Junior Technician (CSE) exam, Advt. No. 1/2026.

## The exam

- CBT on Sunday 29 Nov 2026, 2:30 pm to 5:00 pm, at IIT Kanpur.
- 120 marks in 2.5 hours:
  - Part A, 40 marks, objective: current affairs, quantitative aptitude, numerical ability, logical reasoning, analytical and verbal ability.
  - Part B, 60 marks, objective: CSE domain.
  - Part C, 20 marks, descriptive, English only: official letter, memo/note, report, case study, incident report.
- Parts A and B: +1 for a correct answer, -0.25 for a wrong one. Part C is evaluated only if the minimum is cleared in A and B.
- Final merit is on the written test only. The practical test (JOPT, 1 Dec 2026) is qualifying and covers the same syllabus. Fail JOPT and the candidature is dropped. The JOPT cut-off is "decided suitably" (not published).
- Document verification must be completed before appearing for JOPT, and without an NOC the candidate is not allowed to proceed. Keep the NOC and originals ready.
- Source of truth for the syllabus: `1_2026_311_CSE_InformationSheet.pdf` (official Information Sheet received with the call letter). Where this file and the sheet differ, the sheet wins. The sheet gives no date or venue; those come from the call letter.

## Part B syllabus

Wording below follows the official Information Sheet; items marked (sheet) were missing from earlier versions of this file.

Theory:
- Computer fundamentals: basics, characteristics, generations and classification, input/output, CPU, memory, number systems (sheet).
- C programming and data structures: arrays, pointers, stacks, queues, linked lists, trees, graphs, searching, sorting.
- Operating systems: Linux and Windows, process/memory/storage management, file systems, distributed systems, security.
- Networks: OSI, network performance metrics (sheet), topologies, LAN/VLAN, subnetting and supernetting, TCP/UDP, Wi-Fi, basic security, SAN.
- DBMS: user and role management, queries, optimization, backup and restore, MySQL/MariaDB scripts.

Practical:
- Linux commands and utilities, bash scripting, user and host management, permissions, file systems, socket programming, partition types, OS install, software tools, drivers, packages and their installation, mirrors (sheet).
- LDAP, Git, VirtualBox, KVM, LXC, open-source cloud.
- Mail, web, file and print server install/config/admin; backup; hosting applications in secure and non-secure environments (sheet); firewall setup.
- Cisco IOS basics, DNS, DHCP, VLAN, TFTP, SNMP, tcpdump and other command-line network utilities (sheet).
- Hardware components and assembly, network cable crimping.
- HTML5, CSS, JavaScript, Ajax, PHP, open-source frameworks (sheet).
- Python basics, OOP, data visualization, Django.

- `notes/practical-notes.tex` and `.pdf`: the single notes file for the whole practical syllabus (add new topics to this file, not new files). Practical syllabus only. Same house style as the mocks; use the `\pyq{}` tag for points that came from a past paper, and `lstlisting` for code. Pure CS theory is studied with a separate system, so do not write theory notes here.
- `aptitude/aptitude-notes.tex` and `.pdf`: the single living notes file for quantitative aptitude and reasoning (one chapter per topic; new topics go in this file). It serves all of Ganesh's exams, so the file itself names no exam, no IIT and no marking scheme (told 2026-11-15). Every chapter is a spot-it table plus numbered types T1, T2, ...; each type has Spot it, Mechanism, one solved Sample and a Try it question, with answers at the end of the chapter. No core/stretch or `\pyq{}` tags (they tied the notes to one exam). Type numbers are never reused, with one letter per chapter (T = time and work, S = speed, distance and time, P = percentages, R = ratio and proportion, M = mixtures and alligation, L = profit and loss, C = calendar, K = clocks, A = averages and ages, I = interest, N = number series, Y = syllogisms, D = directions, B = blood relations; avoid O, and give each new reasoning chapter its own unused letter). The generic headings (The one idea, Spot-it table, Shortcuts, Sanity checks, Traps, Answers) are `\subsection*`, so the types number 1.1 to 1.12 in each chapter and only they get PDF bookmarks (`bookmarksdepth=2`). The front page (redesigned 2026-11-15; there is no printed contents any more) is one "Chapters at a glance" table: chapter number, name, type range, the one idea and page number, grouped under "Quantitative aptitude" and "Reasoning". Then the "How to read this file" text, then `\clearpage` and chapter 1. Every chapter's `\section` ends with `\label{ch:X}` (X is its letter), and its table row uses `\ref{ch:X}` and `\pageref{ch:X}`, so chapter and page numbers update by themselves. To add a chapter: the `\label`, one table row in the right group, its letter in the "How to read this file" sentence, and the chapter text (after a `\clearpage`) before `\end{document}`. Page 1 has about 2.8 cm to spare with fourteen chapters (a row takes 0.5 to 1 cm), so about three more rows fit; after that, move "How to read this file" to the top of page 2. Blank space at the foot of a page before a type heading is normal in this file (the heading's `\needspace` makes TeX break there, and many pages in chapters 1 to 11 do it), so do not chase it. The `\addtocontents{toc}{\protect\nopagebreak}` after each `\section` and the `\l@section` redefinition in the preamble are leftovers of the old printed contents and are harmless. Compile three times (delete `.aux`, `.toc`, `.out`, `.log` first) so the page numbers settle, then look at page 1 and every new page. `\keepsamptrue` is set in the preamble (since 2026-11-18), so every Sample line stays with its first working lines in all chapters. `\ans{...}` prints a bold "Answer:" line after a sample's steps. Verify every sample with a script before writing it. Wording is Ganesh's "chair method" (his teachers' term): the LCM of the days is the total number of chairs, and each person makes (LCM divided by their days) chairs a day. Never say "pile" or "bricks". For pipes the tank's litres play the chairs; for men-days-hours questions the total is man-hours. Reasoning chapters use pictures, not numbers, and are checked by an exhaustive model checker written for the job: a model is the set of occupied Venn regions, every group named in the statements has members (so "All A are B" also gives "Some A are B"), a conclusion follows if it is true in every model, "can be" if it is true in at least one, and either-or if neither follows alone but one of the two is true in every model. The syllogism chapter (Y) was built this way. The check corrected my own first draft: the usual list of six valid pairs misses two "All with Some are not" patterns (Y4 rows 7 and 8), so Y4 says eight pairs, and Y5's quick no-conclusion checks were verified never to rule out a pair that has a conclusion. Books differ on "few" (Y9 says to follow the book). The directions chapter (D) was checked with a walker simulation instead: a facing angle plus east and north coordinates, with every rule (quarter turns, angle turns, net position, shadows, facing each other, clock hands) tested against step-by-step simulation and every sample and try-it answer asserted. The blood relations chapter (B) was checked with a kinship checker: random family forests (12 worlds, about 4,000 people; full siblings, monogamous couples), every relation word defined structurally, and every table row, chain, level sum, sample and puzzle tested against them. Statement puzzles are solved over all the worlds: an answer counts only if it holds in every consistent assignment of the named people, and "cannot be determined" needs consistent assignments that give different words. Conventions fixed in B: all named people are different, a couple's children are the couple's own, "father's son" is a brother unless it says "only", a person's sex comes only from a clue (a word, a pronoun or a description, never a name alone), and the in-law word is used for one step only. The preamble has TikZ styles `man`, `woman` and `anyone` (square, rounded and dashed boxes) for family trees. The scripts are not kept in the repo; rebuild the checker or simulation from this description when a new reasoning chapter needs one.

## Mock runner (`runner/`)

A local Go app (no dependencies) for timed CBT exams, topic practice and mistake tracking. Ganesh runs `go run .` in `runner/` and opens http://127.0.0.1:7070 (the Browser-pane config is `.claude/launch.json`, name `runner`).
- `banks/<id>.json`: one file per test: `id`, `title`, `minutes`, `questions`, `partc`, `partc_note`. Each question: `id` (unique across all banks, e.g. `mock-02-q041`), `part` (`A` or `B`), `topic`, optional `passage`, `question`, optional `code` (shown as a code block), four `options`, `answer` (`a` to `d`), `explanation` (the one-line reason) and optional `source` (PYQ tag). Text may use `` `code` `` and `**bold**`; use Unicode for maths (x², −, ×, π). Part C items: `id`, `title`, `words`, `prompt`, `guide` (the guide is shown only after submission).
- Mock 03 and 04 (added 2026-11-18) are harder than 01 and 02 and cover the sheet gaps (Cisco IOS, SNMP, TFTP, tcpdump, mirrors, SAN, generations, performance metrics). They were generated by Python scripts that run every code question (gcc, node, php, python, Git Bash), every SQL question (sqlite3) and every calculation before accepting the answer, and place the correct options evenly (10 per letter in Part A, 15 in Part B). The scripts are not kept; rebuild the same way for new banks. Ganesh may have his own runner open on port 7070: test on another port with a copy of the banks (`-addr`, `-dir`; the `runner-test` launch config) and never touch `runner/data/`. A running server reads the banks only at start, so he must restart it to see new banks.
- Topics must be in the list in `topics.go`, which also groups them into areas. `go run . check` validates every bank (ids, answers, topics, empty fields); the server refuses to start if a bank fails.
- Exams: full paper (bank minutes, Part C written by hand on paper, as in the real exam; the sheet says answers go on answer sheets) or Parts A and B only (minutes − 35). Scoring is on the server, and answers, explanations and Part C guides are not sent to the browser before submission. Each answer change is logged with its time, plus time per question, marked-for-review, visits, leaving the exam window, and time on the Part C tab. Answered-and-marked questions are scored.
- Practice: any set of topics; all questions, unseen only, or open mistakes only; instant feedback with the explanation.
- An open mistake is a question whose latest answer (exam or practice) was wrong.
- Data: `runner/data/attempts/<attempt-id>.json` (one per exam) and `runner/data/practice-log.jsonl`. To review his work, run `go run . report` in `runner/`: every exam, the latest one in detail (wrong and blank questions, topics, answer changes, slowest questions), practice totals by day, topic accuracy and open mistakes. Use it before advising him on what to study.
